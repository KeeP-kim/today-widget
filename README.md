# 오늘은

Windows 바탕화면에 올려두는 작은 위젯. **환율 · 주식 · 코인 · 금리 · 날씨 · 시계**를 한 카드에서 본다.

### 품목별 예측 · 공유 시세와 Codex Spark (v1.047)

오늘은의 **리스트·타일**에서 품목 이름 옆 작은 **예측** 버튼을 누르면 해당 품목의 분석 창이 열린다.
측면·상단·하단 바에서는 세로 점 세 개 **⋮**로 표시한다. 카드·리스트 버튼은 기존 가로·세로·글자 크기의 70%다.
창 제목은 **달러**, **달러트리**, **미국 정책금리**처럼 실제 품목 이름이며, Spark 옆 **?** 버튼에서 연결 도움말을 펼친다.
앱 버전은 수정 1회당 **0.001** 증가한다. 실행 파일명은 **Onuln.exe**로 고정하며, UI 버전 1.047의 .NET 파일 버전은 1.0.47.0이다.

v1.013~v1.047: **성적을 정직하게 재고, 못 맞히면 말하지 않는다.** 자세한 것은 아래 "예측 성적을 어떻게 재는가".

v1.012: PATH 밖에 설치된 Codex 앱 CLI도 찾아 실제 버전을 비교하고, 실행 가능한 최신 CLI로 로그인·분석한다. 모델 선택 옆에는 실제 호출 설정인 **Spark · High / Astra · High**를 표시한다. 추론 강도는 High 고정이며 Extra High/Medium으로 실행하는 설정은 아니다. 붙어 있는 날씨·시계 박스의 배경 두께는 시세 박스를 기준으로 통일한다. 배경색도 같은 색으로 이어 붙여 경계의 턱·색상 단절을 없앤다. 즐겨찾기의 투명한 호버 공간은 별도로 유지하며, 시세 없이 분리된 날씨/시계는 기존 자체 두께를 사용한다. 모니터 배치로 폭만 바뀌어도 다시 측정하고 품목명·가격·등락률 중심선을 맞춘다.

v1.011: **주전망은 검증을 통과한 Spark/Astra 응답 하나**를 표시한다. 기본 계산은 **비교 기준**으로 따로 두고(v1.015 부터 펼친 채로 연다), AI 실패 시 주전망으로 대신 내놓지 않는다. 위 토글은 **참고 / AI 전망**으로 표시하며 기존 기본/극단적 실행 정책을 유지한다. 처음에는 참고·수동 상태이고, AI 전망에서 로그인해야 모델을 호출한다. 입력 자료·모델·스타일·인용 유효성 검증 통과는 미래 적중률 입증과 다르다.
방향 표시는 시나리오 변동률에 일 ±0.1%·주 ±0.3%·월 ±0.5%의 채점 기준을 적용한다. 기준 안에서는 보합으로 표시하고 미세 상승·하락 압력 점수를 구분한다. 각 기간에 근거·반박·전환 조건을 함께 표시하며 원문 설명은 펼쳐 볼 수 있다. AI 그래프에는 주전망 선 하나와 과거 참고 음영을 두고, 가격에는 ‘약’과 시나리오 표시를 붙인다. 날씨는 기존 기상 예보를 유지한다. 모델 점수·가격 환산·가중치 자체를 임의 확대하지 않았으며 적중률 향상을 주장하지 않는다.

v1.010: 위젯에서 연 예측창은 저장된 먼 위치 대신 같은 모니터의 위젯 옆에 배치한다. 상·하단 바는 클릭 지점의 아래·위로, 좌·우측 바는 화면 안쪽으로 연다. 작업 영역에 맞춰 위치·크기를 제한하며 이미 열린 품목을 다시 누르면 현재 위젯 옆으로 가져온다. 위젯 없이 별도로 실행한 분석창의 저장 위치 복원은 유지한다.

v1.009: 공유 시세 수신, 5분 주기의 통신 지연, 접힌 화면에서도 급등·급락 깜빡임이 동작하도록 수정했다. 작은 코인은 반올림한 표시값 대신 원시 가격으로 감지하고, 출처 변경·장시간 단절은 급변으로 계산하지 않는다.
예측 성적은 같은 자료·버전의 기본/선택 모델을 짝지어 비교하고, 기간 중첩과 장마감 시세를 제외한다. 미세 변동은 기간별 보합 기준으로 채점하며, 손상된 기록은 따로 제외한다. 시간순 검증에서 기존 방식과 전체 빈도보다 개선된 경우에만 통계 보조값을 보정한다. 실제 DOGE·BTC·코스피 자료는 적용 기준을 통과하지 못해 보정을 보류했다. **미래 적중률 향상을 달성한 것은 아니다.** 자세한 결과는 [심층 점검 기록](AUDIT-2026-09-08-v1.009.md)에 남겼다.

v1.005: **기본 모드는 규칙·통계 참고만 사용하며 Spark UI·로그인 확인·모델 호출·예약을 실행하지 않는다.**
**AI 전망에서만 Spark 영역이 나타나고 로그인 버튼으로 첫 분석을 시작한다.** 참고로 전환하면 진행 중인 조회/AI/로그인 요청을 취소하고 예약을 멈춘다.
창을 닫으면 그 창의 시세·기사 요청과 Spark 프로세스에 취소를 전달하고 타이머·공유 시세 구독을 해제한다. 이미 처리된 요청의 사용량을 되돌리지는 못한다.
Spark 응답 검증 실패 후에는 원인을 표시하고 **자동 갱신을 중지**한다. 갱신 버튼으로 명시적으로 다시 시도하고 성공하면 주기를 재개한다. 한 갱신에 Spark 모델 요청은 최대 1회다.
인용문을 모델이 재작성하는 대신 기사별 **원문 발췌 번호**를 선택하게 하고 앱이 실제 원문으로 연결한다. 잘못된 기사·발췌 번호·스타일·품목·점수·반박은 계속 검증한다.
실제 도지코인 최신 공개 기사 29건과 과거 800일봉을 사용한 AI 전망 Spark 분석에서 세 기간 응답과 인용 검증을 통과했다.
`tests/run.ps1 -Suite spark-doge-live`는 명시적 실행 때만 실제 Spark 한도를 쓰는 통합 검사다.

v1.004에서 로그인 직후 호출을 막던 잘못된 CLI 인자 `agents.enabled=false`를 제거했다.
`agents`는 역할 설정 테이블이며 하위 에이전트 차단은 `features.multi_agent=false`로 유지한다.
실행 옵션·스키마·한도·모델 권한·인증·TLS·네트워크·파일 접근 오류를 구분해 표시한다.
CLI가 입력 수신 전에 종료해도 실제 원인을 안내하고, 원문 로그의 인증 정보·입력 기사·경로는 오류 메시지로 노출하지 않는다.
실제 설치된 Codex CLI 0.142.4 + GPT-5.3-Codex-Spark에서 연결 성공 및 가상 기사 2개에 대한 1/5/20일 JSON·정확한 인용·반박 검증을 통과했다.
`tests/run.ps1 -Suite spark-live`는 명시적으로 선택할 때만 실제 Spark 한도를 사용하는 통합 검사다. 기본 회귀 검사는 모델을 호출하지 않는다.
버전은 내부 변경 로그·파일 정보·이 문서와 인수인계서에 기록한다.

- 본체에서 연 예측 창은 같은 프로세스의 시세 저장소와 갱신 이벤트를 공유한다. 가격 옆 전일 등락률도 본체와 동일하며 상승은 빨강, 하락은 파랑이다.
- 품목 코드와 종류, 환율의 은행까지 구분한다. 늦은 조회로 최신 시세를 덮거나 다른 품목의 AI 결과·뉴스·통화를 사용하는 경우를 차단한다.
- 미래 그래프는 **오늘은 현재 시세**에서 시작한다. 과거 데이터는 변동 폭 참고용이다. 달러는 ECB 이력, 다른 환율·국내외 주식·지수는 네이버 이력, 코인은 업비트 확정 일봉을 사용한다.
- 주식·환율은 1·5·20거래일, 코인은 1·7·30일이다. 엔화 100단위는 공급자의 동일 단위를 유지하고 해외주식은 USD/JPY 등 실제 응답 통화를 표시한다.
- 금리·경제 지표는 1일·1주·1개월의 달력 기간으로 기사와 정책·발표 근거를 분석한다. 금리 변화는 **%p**다. 월간 ECOS 이력을 일별 자료처럼 복제하지 않는다. 숫자 전망은 근거와 현재값을 갖춘 Spark 응답에 한해 표시한다.
- 날씨를 시세 목록에 추가한 경우에는 같은 지역의 Open-Meteo 일평균 기온 예보를 표시한다. 제공 범위를 벗어나는 1개월 값은 만들지 않는다.
- 이전 버전 본체와 별도로 실행한 분석 EXE는 메모리를 공유하지 않는다. 가격을 실시간으로 맞춰 보려면 **최신 Onuln.exe의 예측 버튼**을 사용한다. 별도 달러 실행 파일도 본체 설정에서 선택한 은행을 읽는다.

데이터 형식 확인: [업비트 일 캔들 API](https://docs.upbit.com/kr/kr/reference/list-candles-days),
[Open-Meteo 예보 API](https://open-meteo.com/en/docs). 네이버 과거 시세 엔드포인트는 2026-09-08 실제 응답으로 확인했다.

각 PC의 Codex CLI와 ChatGPT Pro 로그인을 사용한다. ChatGPT 앱 설치는 필요 없다. 예측 창을 **AI 전망**으로 전환해 **로그인**을 누르면
로그인 상태를 확인하고 필요 시 공식 CLI가 브라우저 로그인을 시작한다. 성공하면 초록 표시등이 켜지고 **첫 Spark 분석을 바로 실행**한다.
기존 CLI 로그인이 있어도 버튼을 누르면 첫 분석을 실행한다. 체크박스는 없다.
Spark 옆 초 숫자를 누르면 **수동 / 60 / 300 / 600 / 1800 / 3600 / 21600초**를 선택한다. **기본은 수동**이며(v1.006~), 주기를 고르면 분석 완료부터 다음 갱신까지 남은 초를 표시한다.
주기는 `sparkRefreshIntervalSec`에 저장하고 열린 분석 창에서 공유한다. 0은 수동, 60~21600초 밖의 값은 300초로 복구한다.
각 창에서 AI 전망의 로그인 버튼을 눌러 활성화해야 자동 분석을 시작한다. 자동 갱신도 매번 Spark 한도를 사용한다. 참고에서는 예약을 멈추며, 다시 AI 전망으로 전환하면 로그인 상태를 유지한 채 주기를 재개한다(실패로 중지된 상태는 수동 재시도 필요).
**연결 해제**는 해당 창의 Spark 호출과 자동 갱신을 멈춘다. Codex 계정 로그인은 유지한다. 창 종료·확인된 로그인 만료 시에도 예약을 멈춘다.
분석 중 요청은 겹치지 않고, 수동 갱신은 30초 간격 제한이 있다. 첫 로그인 후 분석만 이 제한을 적용하지 않는다.
브라우저 로그인이 어려우면 **?** 도움말의 `codex login --device-auth`를 사용할 수 있다(계정에서 기기 코드 로그인 활성화 필요).
`gpt-5.3-codex-spark`(Spark) 또는 `gpt-6-astra`(Astra) 중 고른 모델을 부르며 해당 사용 한도를 소비한다(v1.006~).
별도 API 키를 받거나 저장하지 않으며 실패 시 다른 모델로 자동 전환하지 않는다. CLI 미설치/미로그인/한도 초과 시
연결 안내와 **규칙 참고**를 표시한다. 창을 새로 열면 로그인 버튼을 눌러 다시 활성화한다.

- 단기·중기·장기 전망 옆 **자료 N건**을 누르면 해당 판단의 기사·원문 인용·반대 근거·판단 변경 조건을 펼친다.
- **기간 / 방향 / 자료 수**를 고정된 열로 정렬하고 아래 줄에 ±점수와 핵심 근거를 표시한다. 작은 양·음수 점수는 상승 쪽/하락 쪽으로 구분한다.
- 예상가 카드의 ±값·%는 그래프 시작점인 오늘은 공유 현재 시세 대비 변동이다.
- 갱신 옆 **참고 / AI 전망** 토글을 전환한다(내부 정책 이름은 basic/extreme 그대로다). 참고는 규칙·통계로 요인을 비교하고, AI 전망에서 Spark를 활성화하면 우세 방향의 인과 경로·추가 촉매·반대 논거 대응·주장 철회 조건을 더 깊게 요청한다.
- 스타일별로 마지막 결과를 보관한다. 아직 분석하지 않은 스타일은 갱신 대기를 표시한다. 갱신은 선택된 스타일로 새로운 자료를 분석하며 다른 스타일의 AI 응답은 거절한다.
- AI 전망은 점수를 임의 증폭하는 기능이 아니다. Spark 미연결이면 같은 규칙 계산을 참고로 표시하고 심화 분석에 연결이 필요함을 안내한다.
- 검토 기사 수와 실제 인용 수, 과거 가격 패턴 사례 수를 분리한다. 본문을 읽지 못한 기사는 제목/제공 요약으로 표시한다.
- 공개 기사 제목·요약·본문 발췌와 과거 통계를 공식 CLI를 통해 OpenAI로 전송한다. 기존 Codex 대화나 개인 파일을 프롬프트에 넣지 않는다.
- CLI는 별도 빈 작업 폴더, 읽기 전용 샌드박스, 개인 설정 제외, 셸·멀티에이전트·앱·웹검색 비활성으로 실행한다. 인증은 공식 CLI가 관리한다.
- 임시 응답은 인용 ID·원문 일치·중복·기간·점수 범위·반박 누락을 검사한 뒤 화면에 반영한다. 120초 제한과 창 닫기 취소가 있다.
- 점수는 Spark의 판단 강도이며 상승 확률이 아니다. 뉴스 최대 80점/과거 보조 최대 20점, 일·주·월을 별도 해석한다.
- 파란 미래 선은 점수 방향과 과거 변동 크기를 연결한 **예상 시나리오**다. 환산식은 점수/100 × 과거 10·90백분위 변동의 최대 절댓값이며 학습으로 보정되지 않았다. 회색 선·음영은 과거 참고다.
- 인용 일치 검사는 의미 해석의 정확성이나 미래 적중률을 보장하지 않는다. 기존 과거 역검증은 가격 패턴 모델에만 해당한다.

## 예측 성적을 어떻게 재는가 (v1.013~v1.047)

예측을 내놓는 것보다 **그 예측을 믿어도 되는지 말해 주는 것**을 앞에 둔다.

**상대는 무작위가 아니라 기후값이다.** 3분류 예측을 균등 무작위(0.667)와 견주면
실력이 없는데 있는 것처럼 보인다. 제대로 된 상대는 그때까지의 실현 빈도를 그대로
내놓는 예측기다. 그 기준으로 다시 재고, Brier 를 **불확실성 · 구별력 · 눈금오차**로
나눠 보여 준다. 구별력이 0 에 가까우면 자료가 없는 것이고, 눈금오차가 크면 보정으로
줄일 수 있는 것이다 — 어디를 고칠지가 갈린다. 칸을 나눠 재느라 남는 몫은 잔차로 적는다.

> ★ 아래 표는 **과거 시세로 계산한 것**이고, 살아 있는 예측의 성적이 아니다.
> v1.034 전까지 채점기는 예측 창 안에서만 돌았다. 채점 창은 만기 뒤 6시간인데 하필
> 그 6시간에 그 품목의 창을 열어 둘 일이 거의 없어서, 예측 69건이 쌓이는 동안 채점된
> 것은 **0건**이었다. 게다가 옛 기록(스키마 2)에는 문턱 값이 없어서, 그것을 읽다 난
> 예외가 그날의 채점을 통째로 끊고 있었다. 둘 다 v1.034 에서 고쳤고, 이제 위젯이
> 켜져 있는 동안 만기가 지난 예측이 제때 채점된다. 살아 있는 성적은 이제부터 쌓인다.

실측(2026-09-08 기준, 과거 시세로 계산):

| | 기후값 대비 실력 | 구별력 | 눈금오차 | 표본 |
|---|---:|---:|---:|---:|
| USD/KRW 일간 | −0.032 | 0.008 | 0.030 | 250 |
| BTC 일간 | −0.002 | 0.003 | 0.005 | 249 |

**둘 다 기후값보다 나쁘다.** 그래서 규칙 예측이 스스로 잰 성적이 기후값에 못 미치면
방향을 말하지 않고 **판단 보류**로 둔다. 표본이 모자라면 기권하지 않는다 — 모르는 것과
나쁜 것은 다르다. 이 잣대는 AI 예측에는 걸지 않는다. 과거 가격 패턴을 잰 것이지 AI 를
잰 것이 아니기 때문이다.

**맞고 틀림만 세지 않는다.** 방향 적중률은 얼마나 크게 맞혔는지를 버려서 결론까지
표본이 아주 많이 든다. 예측한 변동과 실제 변동의 상관(IC)을 함께 재고, **이 크기면 몇 건이
더 필요한지**를 성적 줄에 적는다. 지금 성적을 우연과 구분할 수 있는지가 보여야 기다릴지
고칠지 정할 수 있다.

**두 예측이 같이 틀리면 합칠 이유가 없다.** 규칙과 AI 는 같은 기사 묶음을 먹으므로
오차가 함께 움직일 소지가 크다. 오차 상관을 재어 0.8 을 넘으면 그렇게 말한다.

**기사 제목만 보지 않는다.** 근거가 기사뿐이면 숫자로 된 시장 상태를 통째로 놓친다.
이미 쓰고 있는 Frankfurter(ECB) 공표 환율만으로 **달러 강세 지수**를 만들어 1·5·20일
변화율을 화면·AI 프롬프트·예측 기록에 같이 싣는다. EUR·JPY·GBP·CHF 대비 달러값의
기하평균이며 첫 관측일이 100 이다. 네 통화가 모두 있는 날만 쓴다 — 빠진 날을 직전 값으로
채우면 있지도 않은 움직임이 '근거' 로 화면에 뜬다. 관측이 25일 미만이면 아무 말도 하지 않는다.

**미 국채금리도 같이 싣는다.** 달러 방향을 이야기할 때 가장 많이 인용되는 숫자다.
미 재무부의 일별 수익률곡선을 인증키 없이 받아 10년물 수준과 1·5·20일 변화(%p),
그리고 10년−2년 차이를 보여 준다. 금리는 지수로 만들지 않는다 — 환율은 비율이라 첫날을
100으로 맞춰야 뜻이 통하지만 금리는 그 자체가 %이고 차이가 곧 뜻이다. 10년−2년은 **같은
날짜끼리만** 뺀다. 만기 하나가 비는 날이 실제로 있고, 다른 날과 빼면 있지도 않은 역전이 생긴다.
1년치는 260KB라 매번 받기엔 무거워 달마다 나눠 받는다(석 달, 실측 약 78KB). 이 출처는 느릴 때 한 번에 17~19초가 걸려서 **10초짜리 기본 통로로는 한 번도 들어오지 못했다** — v1.038 에서 45초짜리 별도 통로와 6시간 기억을 두어 고쳤다. 시세는 여전히 10초에서 끊는다.

**다만 이 값은 아직 확률에 반영하지 않는다.** 새 재료를 점수에 넣으려면 기후값 대비 실력이
실제로 오르는지 먼저 재야 하는데(위 표), 자료 800일을 특징별로 더 쪼개면 표본이 검증
문턱(30) 아래로 떨어진다. 그래서 지금은 **사람과 모델이 같이 보는 참고값**으로만 두고,
예측 기록에 그때그때의 값을 박아 둔다. 나중에 이 신호가 쓸모 있었는지 IC 로 되짚기 위해서다.
지나서 다시 받아 채운 값으로 재면 미래를 아는 상태로 재는 꼴이 된다.

**보합 범위를 실제 쓰는 값으로 적는다.** 왕복 거래비용을 문턱에 반영해 놓고 화면에는
옛 숫자를 적으면, 보는 사람은 왜 보합이 나왔는지 알 수 없다. 표시와 판정이 같은 함수를 쓴다.

**기사 문장을 다시 읽는다.** v1.012 감사가 남긴 탐침 110개를 지금 규칙으로 다시 돌려,
아직 살아 있는 오독만 골라 고쳤다. 고친 것: '인하 기대 후퇴·약화·축소·중단', 'bets fade',
'pare bets' 가 인하(달러 하락) 근거로 들어가던 것 — 강한 고용·물가 뒤에 가장 흔한 문형이다.
'인하 무산' 은 되돌림으로 잡아 놓고 부정어라서 곧바로 0 으로 지우던 것. '미국 모기지 금리
인하'·'미국 국채금리 내려' 가 연준의 결정(가중치 0.8)으로 잡히던 것. '물가 상승률 둔화' 가
물가 가열과 물가 둔화로 동시에 채점되던 것. 'risks' 를 'rises' 로, 'disagreement' 를
'agreement' 로 읽던 것. 따옴표 안의 쉼표('UBS "연준, …전망"')와 다섯 자 주어('한미 정상,')가
행위자를 떼어 놓아 근거가 0건이 되던 것 — 나눠서 하나도 못 찾은 문장만 통째로 다시 본다.
은행 이름이 앞 절에 남아 애널리스트 의견이 연준 결정과 같은 무게(0.8)로 들어가던 것 —
누가 한 말인지는 절이 아니라 문장의 성질이므로 제목 전체를 보고 판단한다.
각각 반례 검사와 되돌림 검출을 같이 넣었다.

**두 결론이 어긋나면 까닭을 적는다.** 같은 화면에서 점수 줄은 '상승 우세', 방향 줄은
'보합' 을 동시에 말했다. 둘 다 틀린 게 아니라 서로 다른 것을 잰다 — 점수는 근거의 부호이고,
방향은 그 점수로 만든 예상 변동폭이 보합 범위를 넘는지다. 점수 줄의 말을 '근거' 로 못박고,
어긋날 때는 왜 어긋나는지 그 자리에 한 줄 적는다.

**어떤 기사를 들일지도 다시 봤다.** '한은' 이 '신한은행' 안에, '관세' 가 '관세청' 안에 걸려
환율과 무관한 기사가 피드 자리를 차지했다. 요인 점수는 0 이지만 기사 수를 늘려 근거계수를
부풀린다. 반대로 금통위·이창용·파월·FOMC·국고채·외환시장·외국인 순매수 같은 제목에는
'환율' 도 '달러' 도 없어서 통째로 버려지고 있었다. 양쪽 다 고치고 반례를 검사에 넣었다.

**주식·코인 규칙도 같은 방식으로 훑었다.** 'earnings beat' 는 있는데 'beats earnings
estimates' 가 없었다 — 영어는 동사가 앞에 오는데 어순을 하나만 적어 둔 탓에 'cuts full-year
guidance', 'tops expectations', 'downgraded', 'profit warning' 이 전부 0점이었다.
미국 주식 예측에서 실적은 가장 큰 동인인데 그 자리가 비어 있었다. 자사주·배당·리콜·조사도
회사 사건으로 세고, 한국어 쪽에도 같은 짝을 넣었다. 코인에서는 규칙이 이미 있는데 말 하나가
목록에 없어 침묵하던 것들을 채웠다 — '규제 불확실성 해소', '공급량 급증', '기관 매수'.

**규칙이 제 밥값을 하는지 잰다.** 남은 감사 지적은 전부 '규칙이 없어서 침묵' 이다.
규칙을 넣으면 그 침묵은 사라지지만, 차원이 늘면 자료가 더 쪼개져 표본이 문턱 아래로
떨어진다. 그래서 넣기 전에 잴 자리를 먼저 만들었다. 채점이 끝난 기록만 보고 "이 규칙이
방향을 말한 날, 그 방향이 맞았나" 를 규칙별로 세고, 기후값과 견주고, 지금 표본으로
결론을 낼 수 있는지·없다면 몇 건이 더 필요한지를 같이 적는다. 이 장부는 규칙을 자동으로
켜거나 끄지 않는다 — 사람이 보고 정한다.

**유사 사례의 조건을 바꿨다 (v1.039).** 지금까지 쓰던 조건(5일 방향 × 20일 변동성)을 800일
시세로 재 보니 **기후값보다 유의하게 나빴다** — 사례별 Brier 차이의 t 값이 합쳐서 +3.02,
USD/KRW +2.23, JPY/KRW +2.47. 정보가 없는 게 아니라 틀린 정보였다. 미리 정해 둔 후보 여섯 개를
같은 잣대로 재서(저장소에 넣지 않은 감사 도구로 측정) 미리 정한 채택 규칙(일간에서
5품목 중 4개 실력 > 0, 200회 이상)을 통과한 것은 **전일 등락 부호** 하나였다.

| 특징 | BTC | USD/KRW | JPY/KRW | DOGE | Dollar Tree | 합쳐서 |
|---|---:|---:|---:|---:|---:|---:|
| 종전 (5일 방향 × 20일 변동) | +0.30 | **+2.23** | **+2.47** | +0.49 | −0.14 | **+3.02** |
| 전일 등락 부호 | +1.83 | −1.36 | −0.97 | −0.48 | −0.74 | −1.52 |

(t 값. 음수가 기후값보다 낫다. ±1.96 밖이면 우연으로 보기 어렵다.)

<sub>여기서 잰 다섯 품목은 측정 당시의 기본 묶음이다. v1.047 에서 기본값을 누구에게나
무난한 것(비트코인 · 애플)으로 바꿨으므로 지금 처음 켰을 때 담기는 것과는 다르다.
잰 값은 잰 그대로 둔다 - 나중에 바꾼 기본값에 맞춰 고치면 측정이 아니게 된다.</sub>

**정직하게 말하면 새 조건은 중립이다** — 기후값과 유의하게 구별되지 않는다(−1.52). 유의하게
해로운 것을 중립으로 바꾼 것이지, 맞히기 시작한 것이 아니다. 후보를 여섯 번 시도한 것은
채점 변경 목록에 올렸다. 살아 있는 예측의 성적은 여전히 쌓여야 안다.

**말할 수 없는 기간은 그렇다고 말한다.** 보합 문턱은 고정 비율(일 ±0.1%·주 ±0.3%·월 ±0.5%)
인데 품목마다 변동성이 서너 배 다르다. 그래서 같은 문턱이 어떤 품목에는 사소하고 어떤
품목에는 벽이 된다. 여기에 24시간 뉴스의 기간 가중치(주 0.5·월 0.25)가 겹친다.

실측으로 보합을 벗어나는 데 필요한 근거(최대치 대비, 일간·주간·월간):

| 품목 | 10~90% 일간 변동폭 | 일간 | 주간 | 월간 |
|---|---:|---:|---:|---:|
| USD/KRW | 0.80% | 21% | 54% | **65%** |
| BTC | 2.52% | 7% | 18% | 27% |
| Dollar Tree | 3.21% | 5% | 14% | 23% |

**USD/KRW 월간은 사실상 기사가 만장일치여야 방향이 난다.** 다른 품목은 여유가 있다.
잣대를 지금 또 옮기면 이제 막 쌓이기 시작한 성적을 읽을 수 없으므로 고치지 않고, 대신
그 기간의 방법 설명에 **얼마나 필요한지를 적는다.** 말하지 않으면 보는 사람은 '월간은
늘 보합' 을 시장이 조용해서라고 읽는다. (제대로 고치려면 고정 비율 문턱을 품목의
변동성에 맞춰 잡아야 하는데, 그건 잣대를 바꾸는 일이라 표본이 쌓인 뒤에 정한다.)

**몇 번 고쳤는지 밝힌다.** 여러 번 고쳐 보고 좋아 보일 때 고르면 그 성적은 우연일 수 있다.
채점에 손댄 판의 수와 목록을 화면에 적는다.

**과거 검증이 미래를 읽지 않는지 스스로 확인한다.** 마지막 봉만 망쳐도 그 앞 사례들의
성적이 바뀌면 미래를 읽은 것이다. 가운데를 망치면 반드시 달라져야 한다는 대조군을 함께 둔다.
AI 는 과거로 백테스트하지 않는다 — 살아 있는 예측만 앞으로 채점한다.

**기록이 스스로를 설명한다.** 예측 기록에 점수 성분·신뢰도 입력값·기사별 본문 읽음 여부를
남기고, AI 인용은 번호 대신 **기사 주소와 검증된 원문 발췌**로 박는다. 나중에 기록 하나만
있으면 "이 주장이 어느 기사의 어느 문장에서 나왔는가" 를 확인할 수 있다.
옛 기록은 그때 쓰던 문턱으로 채점한다 — 잣대를 바꿔도 지난 성적이 흔들리면 안 된다.

**비용 아래 구간은 방향으로 세지 않는다.** 일간 ±0.1% 는 거의 모든 자산의 왕복 거래비용
아래라, 그 안을 두고 상승·하락을 말하는 것은 실제로 아무 뜻이 없다. 설정 `roundTripCost` 에
`fx:FX_USDKRW=1.5, coin:KRW-BTC=0.1` 처럼 품목별 왕복 비용(%)을 넣으면 보합 문턱이 그 위로
올라간다. **기본값은 비워 둔다** - 수수료·세금·스프레드는 거래소와 상품마다 다르고 해마다
바뀌므로 그럴듯한 숫자를 기본으로 넣지 않는다. 안 넣었으면 화면이 "반영되지 않았습니다" 라고 말한다.

**코인을 코인답게 읽는다.** 전에는 코인 규칙이 '연준 할인율' 과 '전쟁' 둘뿐이라 ETF 자금유입·규제·
해킹·스테이블코인 발행 같은 기사가 전부 0점이었다. 전달 경로가 분명한 것만 규칙으로 넣되, 미리 알려진
일정(반감기)이나 근거가 약한 신호(고래 지갑 이동)는 가중치를 낮추고 반대 해석을 함께 적는다.
결말은 원인보다 앞세운다 - '소송 기각' 은 소송이 아니라 해소로 읽는다.

**기사 본문을 더 읽는다.** 한 번에 본문까지 읽는 기사를 9건에서 24건으로 늘렸다
(`articleBodyLimit`, 0이면 제목만, 상한 60). 고르는 기준도 바꿨다 — 규칙이 요인을 많이 뽑은
기사부터 읽으면 이미 아는 것만 더 읽게 된다. 최신 것을 먼저 읽는다.

그 밖에: 뉴스 규칙이 부정문("인하 안 한다")·소수점("3.50%로 인하")·쉼표("연준, … 인하")를
제대로 읽고, 무역·환율 "전쟁"을 무력 분쟁으로 세지 않는다. 예측 창 글자 크기는
**Alt+-** / **Alt++**(되돌리기 **Alt+0**)로 바꾼다. 비교 기준은 접지 않고 펼친 채로 연다.

## 실행

**받아서 쓰기** — [Releases](https://github.com/KeeP-kim/today-widget/releases) 에서
`Onuln_portable.zip` 을 받아 원하는 폴더에 풀고 `install.cmd` 를 실행한다.
둘 곳을 묻는 단계에서 Enter 를 누르면 푼 자리를 사용한다. 내려받기·바탕화면처럼
공용으로 쓰는 폴더라면 그 아래 `오늘은` 폴더를 사용한다.
낱개 파일을 받았다면 같은 폴더에 두고 `launch.vbs` 를 실행한다.

**직접 빌드하기** — 저장소에는 바이너리를 두지 않는다.

1. `build.cmd` 더블클릭 (최초 1회)
2. 바탕화면에 바로가기를 만들거나 `launch.vbs` 를 더블클릭

종료는 위젯 **우클릭 → 종료**.

## 달러 분석 창

본 위젯 우클릭 → **달러 분석 창…** 으로 연다. 합체·도킹하지 않는 독립 창이며,
닫아도 본 위젯은 계속 동작한다. **갱신** 또는 `F5` 로 환율 이력과 뉴스를 조회한다.
첫 실행 시 한 번 조회하고, 이후 자동 주기 조회는 하지 않는다. 연속 갱신은 30초 간격이다.

기존 위젯을 켜 둔 채 분석 창만 실행하려면 `build.ps1 -CI -AnalysisOnly` 로
`Onuln.Analysis.exe` 를 만든 뒤 실행한다. 이 모드의 설정은 `dollar-analysis.json` 에
별도로 저장되어 본 위젯의 설정과 서로 덮어쓰지 않는다.

- **첫 화면:** 기간별 방향·점수·근거 한 줄, 실제 자료 수, 일·주·월 예상 환율과 ±원·%, 미래 그래프를 표시한다.
  계산식·전체 뉴스·과거 통계·검증 결과는 기본적으로 접힌 **상세 보기**에서 확인한다.
  새 뉴스 방향이 없으면 **과거 참고** 또는 **변화 주시**, 표시 점수가 0.0이면 **혼조**, 작은 양수·음수는 **상승 쪽 / 하락 쪽**으로 구분한다.
  뉴스 근거 없이 그리는 가격은 **통계 참고**로 표시한다. 공개 본문을 수집한 기사는 원문 범위를 별도로 표시한다.
- **일간 / 주간 / 월간:** 최신 ECB 기준환율을 기준으로 1 / 5 / 20공시일 후의 과거 누적 변동 비율.
  주간·월간은 달력상 정확한 일주일·한 달과 다를 수 있다. 보합 범위는 각각 ±0.1% / ±0.3% / ±0.5%.
- **규칙 참고 점수 (Spark 미사용):** -100~+100 방향 지표. 뉴스 최대 80점, 과거 최대 20점에서 상승·하락 근거를 상쇄한다.
  기초 계수 0.5에 출처별 가중치(주요 언론 0.9/기타 0.6), 시간 감쇠, 같은 요인의 교차 보도(0.75~1), 수집 누락을 반영한다. 단기 뉴스의 주간·월간 가중치는 0.5·0.25이다.
  중복 제목 및 같은 매체의 같은 주제·방향 반복을 제한하며, 방향 기사 8개 미만은 기여를 낮춘다(v1.014 에서 4개에서 올렸다 — 같은 보수성이 분모와 여기 두 곳에 겹쳐 걸리던 것을 한쪽으로 모았다).
  가중치는 초기 규칙이며 학습·검증된 상승 확률이 아니다. 과거 가격 패턴은 참고 기여로 유지하며 새 경제 요인 확인 여부를 구분한다.
- **앞으로의 그래프:** 최신 ECB 환율에서 +1/+5/+20공시일 추정점을 연결한다.
  회색은 유사 사례 중앙값, 파랑은 종합 점수 방향과 과거 변동 크기를 반영한 시나리오다
  (점수 / 100 × 과거 10·90백분위 변동의 최대 절댓값). 0.0점은 기준값 유지, 뉴스 판단이 없으면 과거 중앙값을 참고한다.
  음영은 과거 10~90백분위로 미래 80% 신뢰구간이 아니다.
  은행 고시와 ECB 기준은 섞지 않는다. 뉴스 근거가 없으면 통계 참고선만 표시한다.
  가격 평균 절대오차·환율 유지 기준 오차·범위 포함률을 과거 시점별 자료만 사용해 검증한다.
  이 검증은 통계 중앙값에만 적용된다. 뉴스 결합 추정은 과거 뉴스 데이터가 없어 미검증이다.
- **과거 유사 사례:** 최근 3년에서 **전일 등락 부호**가 같은 날들이다(v1.039). 전에는 5공시일 방향과 20공시일 변동성으로 구분했는데, 800일로 재 보니 그 구분은 기후값보다 유의하게 나빴다(아래 "예측 성적을 어떻게 재는가").
  유사 사례 30회 미만이나 기준일이 7일 넘게 오래되면 비율을 표시하지 않는다.
- **반대 근거:** 단순 과거빈도보다 낮은 검증 성적, 적은 표본, 반대 추세·뉴스를 함께 표시한다.
  과거 빈도는 미래 확률이 아니며, 사례 간 중복과 시장의 뉴스 선반영 여부는 남은 한계다.
- **뉴스:** 연합뉴스 경제·국제, 한국경제 경제·국제, BBC 경제·세계 RSS와 Google News의
  환율/연준/한은/한미/국제정세/기업투자/엔캐리/워시·트럼프/CNN·BBC 검색을 갱신마다 조회한다.
  24시간 내 기사만 사용하며 중복 제목을 제거한다. 직접 RSS는 피드당 최대 12건, 검색은 최대 6건이다.
  CNN 직접 RSS는 TLS 연결 실패로 사용하지 않고 검색 피드를 사용한다. 장애·누락 수를 표시한다.
  직접 링크를 제공하는 매체에서 매체당 최대 8건, 총 24건까지 공개 본문 발췌를 추가로 읽는다(`articleBodyLimit`, 기본 24·최대 60).
  본문을 못 읽으면 제목·제공 요약으로 계산하고 기사마다 실제 분석 범위를 표시한다.
- **경제 요인 조합:** 금리/물가/고용, 한국 수급·정책 위험, 통상, 전쟁·유가, 기업 해외 투자,
  일본 금리·엔캐리의 전달 경로와 반대 해석을 조합한다. 인물 이름 자체는 점수를 주지 않는다.
  발언·전망·위협은 확정 사건보다 낮게, 부정·과거 사건은 현재 방향으로 합산하지 않는다.
  같은 기사 안의 상반된 요인은 상승·하락 양쪽에 기록한 뒤 상쇄한다.

## 빌드

```
build.cmd
```

Windows에 기본 포함된 `csc.exe`(.NET Framework 4.8)만 사용한다. Visual Studio나 SDK 설치가 필요 없다.
결과물은 두 개다.

| 파일 | 용도 |
|---|---|
| `Onuln.exe` | 직접 실행. 가장 가볍다 (작업관리자 기준 평균 12MB) |
| `Onuln.dll` | 런처가 메모리로 올려 실행 (약 90MB) |

개발 중 회귀 검사는 `powershell.exe -NoProfile -File tests/run.ps1` 로 실행한다.
손상된 설정 원본 보존, 정상 JSON·설정 저장, 시세 접기·복원·최소화·닫기 상태,
샘플 설정과 어셈블리 버전 일치를 확인한다. 화면을 띄우거나 외부 API 를 호출하지 않는다.

로컬 배포본은 `Onuln_portable.zip` 이며, `package/오늘은` 과 `portable/오늘은` 은
그 내용을 풀어 둔 폴더다. `dist` 의 버전명이 붙은 ZIP 과 `_old` 는 과거 산출물이므로
현재 배포에 사용하지 않는다. 공개 배포본은 GitHub Releases 의 CI 산출물을 사용한다.

### 왜 DLL 이 같이 나오나

Windows 11의 **Smart App Control** 은 서명되지 않은 exe 실행을 차단한다.
직접 빌드한 exe는 서명이 없으므로 환경에 따라 막힌다.

그래서 `launch.vbs` → `launch.ps1` 런처가 이렇게 동작한다.

```
launch.vbs → launch.ps1
              ├─ Onuln.exe 를 먼저 시도          (되면 이걸로 끝)
              └─ 막히면 Onuln.dll 을 메모리로 로드
                 (powershell.exe 는 MS 서명 파일이라 차단되지 않고,
                  파일 '실행'이 아니라 어셈블리 '로드'라 정책에 걸리지 않는다)
```

차단 여부는 이벤트 뷰어 `Microsoft-Windows-CodeIntegrity/Operational` (Event ID 3077 / 3118)에서 확인할 수 있다.

- JSON 파서에 재귀 깊이 제한 (깊게 중첩된 입력으로 프로세스를 죽일 수 없게)

## 개발 노트 — 같은 데서 두 번 막히지 않으려고 적어둔 것

- **`TargetFramework` 특성이 없으면 TLS가 깨진다.**
  `csc` 로 직접 빌드한 어셈블리에 이게 없으면 .NET이 4.0 호환(quirks) 모드로 돌린다.
  구형 TLS로 핸드셰이크를 시도해서 Cloudflare 뒤에 있는 서버와 연결이
  `SSL/TLS 보안 채널을 만들 수 없습니다` 로 실패한다. 네이버는 통과해서 **환율만 멀쩡한** 상태가 된다.

- **`AutomaticDecompression` 에 `Deflate` 를 넣지 말 것.**
  서버가 zlib 헤더가 붙은 deflate를 보내면 .NET의 `DeflateStream` 이 풀지 못한다. gzip만 쓴다.

- **`ServicePointManager.SecurityProtocol` 을 건드리지 말 것.**
  `SystemDefault` 로 두면 OS가 알아서 협상한다. `Tls12` 로 고정하면 오히려 일부 서버와 깨진다.

- **WPF에서 애니메이션이 걸린 속성은 값을 직접 넣어도 무시된다.**
  흔들림 애니메이션이 각도를 점유한 상태에서 `Angle = 8` 을 대입해도 아무 일도 일어나지 않는다.
  `BeginAnimation(prop, null)` 로 먼저 떼어내야 한다.

- **드래그 판정에 `GetPosition(this)` 를 쓰지 말 것.**
  마우스를 캡처한 상태에서 창 기준 좌표가 갱신되지 않는 경우가 있다. `GetCursorPos` 로 화면 절대 좌표를 쓴다.

- **`.cmd` 파일에 한글을 넣지 말 것.**
  cmd는 ANSI 코드페이지로 읽어서 UTF-8 주석이 깨지고 파싱이 망가진다. 한글이 필요하면 `.ps1`(UTF-8 BOM)로 뺀다.

- **PowerShell 리플렉션 호출 시 인자가 `PSObject` 로 감싸진다.**
  `$m.Invoke($null, @($a, $b))` 는 실패한다. `New-Object object[]` 로 배열을 만들어 `[string]` 으로 넣어야 한다.

- **WPF 기본 `MenuItem` 템플릿에는 흰색 아이콘 컬럼이 박혀 있다.**
  색 속성만 바꿔서는 다크 메뉴가 안 된다. `ControlTemplate` 을 통째로 교체해야 하고 하위 메뉴 팝업도 직접 만들어야 한다.

- **인증을 요구하는 프록시 뒤에서는 자격 증명을 넘겨줘야 한다.**
  `HttpClientHandler` 는 `UseProxy = true` 만으로는 인증을 요구하는 프록시에 응답하지 못해
  모든 요청이 407 로 죽는다. `WebRequest.GetSystemWebProxy()` 에 `CredentialCache.DefaultCredentials`
  를 물려 핸들러에 넣어야 그런 망에서 동작한다. 프록시가 없는 환경에서는 아무 영향이 없다.

- **빌드 스크립트가 DLL 런처를 못 죽이면 구버전이 계속 돈다.**
  DLL 폴백으로 실행 중이면 프로세스명이 `powershell.exe` 라 exe 이름으로는 안 잡힌다.
  새로 띄운 최신 버전은 중복 실행 방지로 즉시 종료되어, **고쳐도 안 고쳐진 것처럼 보인다.**

## 내려받은 파일이 차단될 때

Windows 11 의 **Smart App Control** 은 서명이 없는 실행 파일을 막는다. 예외 등록이라는 것이 없고,
한번 끄면 Windows 를 다시 깔기 전에는 켤 수 없으므로 **끄지 말 것.**

대신 이 프로젝트는 두 벌로 나온다.

| | 언제 쓰나 |
|---|---|
| `Onuln.exe` | Smart App Control 이 꺼져 있거나, 서명된 릴리스를 받았을 때 |
| `Onuln.dll` + `launch.vbs` | 차단될 때. PowerShell 이 DLL 을 **메모리로 올려** 실행한다 |

`launch.vbs` 는 exe 를 먼저 시도하고, 막히면 알아서 DLL 쪽으로 넘어간다. 그냥 이것만 써도 된다.
(DLL 경로는 메모리를 20MB 대신 90MB 정도 쓴다.)

### 서명 (Code signing)

현재 CI 의 코드 서명 단계는 비활성화되어 있어 산출물에 서명이 붙지 않는다.
SignPath 승인과 CI 설정을 마친 뒤 서명을 적용할 예정이다.
직접 빌드한 파일에도 서명이 없다.

설정과 즐겨찾기는 전부 PC 안(`config.json`, `앱저장/`)에만 남는다.

밖으로 나가는 통신은 **화면에 보여줄 값을 가져오는 것**뿐이며, 그 상대는
[데이터 출처](#데이터-출처) 표에 적힌 곳과, 예측 기능이 쓰는 다음 세 갈래가 전부다.

| 어디로 | 무엇 | 언제 |
|---|---|---|
| `news.google.com` · `yna.co.kr` · `hankyung.com` · `bbc.co.uk` | 뉴스 제목과 공개 본문 발췌 | 예측 창을 열 때 |
| `api.frankfurter.dev` (ECB) | 환율 이력, 달러 강세 지수 | 예측 창을 열 때 |
| `home.treasury.gov` (미 재무부) | 국채 수익률곡선 | 예측 창을 열 때 |

셋 다 인증키가 없고 계정도 없다. 보내는 것은 주소뿐이며 개인 정보는 실리지 않는다.
그중 두 가지만 더 짚어 둔다.

| 무엇이 나가나 | 어디로 | 왜 | 끄는 법 |
|---|---|---|---|
| 접속 IP | `ipapi.co` · `ipwho.is` | 첫 실행 때 위치를 짐작해 날씨 지역을 정한다 | 지역을 직접 넣으면 다시 부르지 않는다 |
| 조회하는 종목·지역 | 네이버 · 업비트 · 한국은행 · Open-Meteo | 시세와 날씨를 받아오려면 무엇을 원하는지 알려야 한다 | 그 섹션을 닫으면 조회 자체를 멈춘다 |
| 접속 IP | `api.github.com` | 하루 한 번 새 버전이 나왔는지 본다 (v0.88 부터 기본으로 켜짐) | 우클릭 → **새 버전 알림** 을 끈다 |

접어두거나 닫은 섹션은 **네트워크 호출을 하지 않는다.**

새 버전 확인은 **v0.88 부터 기본으로 켜져 있다.** 하루에 한 번
`api.github.com` 으로 GET 이 한 번 나가고, 그게 전부다 — 본문도 쿠키도 인증 헤더도 없고,
앱 버전이나 설치 식별자도 붙지 않는다. GitHub 쪽에서 보이는 것은 여느 웹 요청과 같은 IP 뿐이다.
**우클릭 → 새 버전 알림** 을 끄면 이 조회도 하지 않는다.

### v1.006 — 비교 기록과 모델 선택
- 분석 기본 갱신은 수동. 기존 v1.005 이하 설정도 최초 로드 시 수동으로 이행하며, 이후 사용자가 지정한 주기를 저장한다.
- AI 전망에서 Spark / Astra를 선택한다. 변경 시 진행 중 요청을 취소하고 갱신 버튼을 기다린다. 다른 모델로 자동 대체하지 않는다.
- PATH의 codex.exe를 npm 내장 CLI보다 먼저 사용한다. 구형 CLI는 Astra를 거절할 수 있다.
- prediction-history/에 UTF-8 XML로 당시 기본·선택 AI 예측, 시세, 기사, 점수, 모델, 버전을 함께 기록한다. 원본 예측과 채점 파일을 분리해 미래 정보로 덮어쓰지 않는다.
- **그 품목의 시세를 실제로 받고 있는 동안** 들어오는 동일 출처 시세로 채점한다. 채점에는 5분 이내의 신선한 시세가 필요하므로, 시세 칸을 접어 두거나 위젯이 꺼져 있으면 그 시간만큼 표본을 잃는다. 조회를 끈 것은 사용자의 선택이므로 몰래 켜지 않는 대신, **놓쳐서 영영 채점할 수 없게 된 건수를 분석 창에 적는다.** (v1.034 전에는 분석 창이 열려 있을 때만 채점기가 돌았고, 그래서 예측 69건 중 채점된 것이 0건이었다.) 코인은 1·7·30달력일, 그 외는 1·5·20평일의 같은 시각부터 6시간 안에 수신한 첫 시세를 사용한다. **평일을 세는 요일은 그 거래소가 있는 곳의 요일이다**(v1.040) — 미국 장의 뒷부분은 한국 시각으로 이미 다음날이라, 한국 요일로 세면 목·금 오후장 예측의 만기가 일요일에 떨어져 영영 채점되지 않았다. **환율은 고시된 날짜가 오늘이 아니면 채점에 쓰지 않는다**(v1.040) — 네이버는 휴일에도 전날 고시환율을 돌려주고 수신 시각만 새것이라, 그대로 두면 멈춘 값으로 채점한다. 휴장일 캘린더와 거래소 체결 시각 보정은 아직 없으므로 엄밀한 거래일 백테스트가 아닌 관측 성적이다. 미수신 기간은 억지로 채점하지 않는다.
- 방향 일치율과 기준가격 대비 절대 오차율, 가격 유지 오차율 표시. 중첩·반복 예측을 포함하며 확률이나 독립 검증 성적으로 해석하지 않는다. 경제 지표·날씨 기록은 현재 제외한다.
- 브리프 흰색, 브리프와 가장자리 시세 글자 -0.05em 자간·단어 유지 줄바꿈. 폭보다 긴 단어는 가로 폭을 맞추어 유지한다.
- 정확도 개선의 5개 작업 기준은 PREDICTION-ROADMAP.md에 유지한다. 시장 데이터 확장 및 학습 가중치는 아직 적용하지 않았다.


v1.007: 분석 창 현재 가격 옆에 등락률(14px, 10px 간격)과 ▲/▼를 표시한다. 반올림한 보합은 화살표 없이 중립색이다. 기본 브리프는 실제 종합 결론을 먼저 표시하고 개별 기사 요인을 구분한다. 채점 완료 자료가 없는 상태에서 예측 가중치를 임의로 보정하지 않았다.


v1.008: 시세 항목 더블클릭은 상세 예측을 연다. 사이트 이동은 예측창 가격 오른쪽 목적지 버튼으로 제공한다. AI가 한 기간에 같은 기사를 여러 번 인용하면 모든 인용을 검증한 뒤 기사당 한 근거로 병합한다. 상이한 역할은 mixed로 보존하고 서로 다른 원문 발췌는 구분하여 함께 표시한다. 기사 수를 중복 가산하지 않으며 모델의 원래 점수는 변경하지 않는다.
